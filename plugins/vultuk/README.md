# Vultuk

Personal skills for daily workflows. Plugin ID: `vultuk`. Version: `0.1.44`.

## Skills

| Skill | Purpose and when to use | Setup |
| --- | --- | --- |
| [how](skills/how/SKILL.md) | Explicit code walkthroughs, subsystem architecture, runtime flow, ownership, and layering questions before changes | Codebase read/search access; optional subagents with sequential fallback |
| [create-verification-skill](skills/create-verification-skill/SKILL.md) | Generate a project-local verification skill and feature map for real app workflows | Target codebase, project runtime/build tools, suitable harness, and disposable fixtures |
| [maintain-verification-skill](skills/maintain-verification-skill/SKILL.md) | Audit and repair verification documentation, feature maps, and owned harnesses using source and live coverage | Existing verification skill and map, runnable test environment, live harness; optional subagents |
| [why](skills/why/SKILL.md) | Investigate historical rationale and tradeoffs with cited, confidence-qualified evidence | Target code/history; available authorized connectors or authenticated `gh`; optional subagents |
| [poteto-mode](skills/poteto-mode/SKILL.md) | Explicit engineering workflow and style guidance with task-specific playbooks | [Compatibility guide](skills/poteto-mode/compatibility.md); optional Bun/Node/Git helpers and authorized GitHub access |
| [principle-attack-the-premise](skills/principle-attack-the-premise/SKILL.md) | Apply when two or more fixes that share one premise have failed the same gate. Take a census of which actors hold the imbalance before the next fix, then question the premise instead of writing another fix that assumes it. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-boundary-discipline](skills/principle-boundary-discipline/SKILL.md) | Apply when wiring validation, error handling, or framework adapters. Concentrate guards at system boundaries (CLI, config, network, external APIs); trust internal types and keep business logic in pure functions. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-build-the-lever](skills/principle-build-the-lever/SKILL.md) | Apply to any non-trivial work, not just bulk work: edits, migrations, analyses, checks. Build the tool that does it or proves it (codemod, script, generator, or a skill your subagents follow) instead of working by hand. The tool is the artifact a reviewer can rerun. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-encode-lessons-in-structure](skills/principle-encode-lessons-in-structure/SKILL.md) | Apply when you catch yourself writing the same instruction a second time, or notice a recurring correction. Encode the rule as a lint, metadata flag, runtime check, or script instead of more text. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-exhaust-the-design-space](skills/principle-exhaust-the-design-space/SKILL.md) | Apply when facing a novel UI interaction or architectural decision with no precedent in the codebase. Build 2-3 competing prototypes and compare side by side before committing. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-experience-first](skills/principle-experience-first/SKILL.md) | Apply when product, UX, or feature-scope tradeoffs come up. Choose user delight over implementation convenience; ship fewer polished features over more rough ones. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-explain-the-number](skills/principle-explain-the-number/SKILL.md) | Apply before you trust, report, or act on a number you measured: a speedup, a regression, a throughput, a latency, or an eval result. Find what limits it, and rule out that it measured something other than the work you think. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-fix-root-causes](skills/principle-fix-root-causes/SKILL.md) | Apply when debugging. Trace each symptom to its root cause and fix it there; reproduce first, ask why until you reach it, resist nil-check guards that silence crashes. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-foundational-thinking](skills/principle-foundational-thinking/SKILL.md) | Apply before writing logic: choosing core types and data structures, sequencing scaffold-vs-feature work, asking what concurrent actors share. Get the data structures right so downstream code becomes obvious. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-guard-the-context-window](skills/principle-guard-the-context-window/SKILL.md) | Apply when context is filling up: large outputs, long files, repeated reads, fan-out planning. Route bulk to subagents; keep summaries in the main thread, not raw payloads. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-laziness-protocol](skills/principle-laziness-protocol/SKILL.md) | Apply when refactoring, evaluating diff size, or tempted to add abstractions, layers, or signal threading. Bias toward deletion and the smallest change that solves the problem. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-make-operations-idempotent](skills/principle-make-operations-idempotent/SKILL.md) | Apply when designing commands, lifecycle steps, or processing loops that run amid crashes, restarts, and retries. Converge to the same end state regardless of partial prior runs. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-migrate-callers-then-delete-legacy-apis](skills/principle-migrate-callers-then-delete-legacy-apis/SKILL.md) | Apply when introducing a new internal API while old callers still exist. Migrate callers and delete the old API in the same wave instead of preserving compatibility layers. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-minimize-reader-load](skills/principle-minimize-reader-load/SKILL.md) | Apply when reviewing or shaping code that's hard to trace. Follow applicable project tools and permissions. |
| [principle-model-the-domain](skills/principle-model-the-domain/SKILL.md) | Apply when writing stateful logic, or when code branches a lot or repeats a shape assumption across files. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-never-block-on-the-human](skills/principle-never-block-on-the-human/SKILL.md) | Apply when tempted to ask 'should I do X?' on reversible work. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-outcome-oriented-execution](skills/principle-outcome-oriented-execution/SKILL.md) | Apply during planned rewrites and migrations with explicit phase boundaries. Converge on the target architecture; don't preserve smooth intermediate states with throwaway compatibility code. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-prove-it-works](skills/principle-prove-it-works/SKILL.md) | Apply after completing a task, before declaring done. Verify against the real artifact (run the feature, read the actual value, inspect the diff), not a proxy, self-report, or 'it compiles.' | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-redesign-from-first-principles](skills/principle-redesign-from-first-principles/SKILL.md) | Apply when integrating a new requirement into an existing design. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-separate-before-serializing-shared-state](skills/principle-separate-before-serializing-shared-state/SKILL.md) | Apply when concurrent actors might write to the same file, branch, key, or state object. Eliminate the sharing first; serialize structurally only when one shared writer is a real invariant. | Relevant project or text context; no new runtime dependency. Follow applicable project tools and permissions. |
| [principle-sequence-verifiable-units](skills/principle-sequence-verifiable-units/SKILL.md) | Apply to multi-step work (sweeps, migrations, runs of similar edits) and to how you stack commits and PRs. Follow applicable project tools and permissions. |
| [principle-subtract-before-you-add](skills/principle-subtract-before-you-add/SKILL.md) | Apply when sequencing an addition, refactor, or rewrite. Follow applicable project tools and permissions. |

Follow applicable project tools and permissions. |

Follow applicable project tools and permissions. |
